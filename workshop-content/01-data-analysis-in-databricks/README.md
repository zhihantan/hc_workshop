# Section 01 — Data Analysis in Databricks

**Status:** Draft — workspace validation and facilitator rehearsal required
**Time:** 9:45 AM–11:15 AM (90 minutes)

Participants investigate Unicorn Finance's 0% smartphone promotion and first-payment-default pattern while learning how analytical assets run and are operated on Databricks.

## Outcomes

By the end of the section, participants can:

1. Choose notebook, jobs, or SQL warehouse compute based on the workload rather than habit.
2. Explain when serverless is the default, when classic customization is justified, and how Serverless, Pro, and Classic SQL warehouses differ.
3. Explore Unity Catalog data with PySpark and SQL, then change the analytical grain of an inherited investigation.
4. Persist that investigation as a participant-specific Delta table and inspect its schema evolution and history.
5. Trace one governed FPD5 definition from a Metric View into an AI/BI dashboard and private Genie Agent.
6. Inspect the SQL workload generated by the dashboard or Agent and distinguish queueing from spill.

## Workshop flow

- **Opening decision framework:** choose the workload surface first, then the operating model; distinguish Serverless, Pro, and Classic only where those SQL warehouse types apply.
- **Connected participant workflow:** discover governed data, derive FPD5, change the analytical grain, persist the result with Delta, and trace the same metric into a dashboard and Genie Agent.
- **Closing operational inspection:** use Warehouse Monitoring, Query History, and Query Profile to inspect the workload the section generated.

The section prioritizes one complete developer workflow over unrelated feature coverage.

- `slide-outline.md` — recommended presentation slides and transitions to live demonstration.

Each participant's notebook creates only:

```text
hc_workshop.workshop_labs.unicorn_<runner_id>_fpd_investigation
```

The notebook derives `runner_id` from the current user's full workspace identity and adds a short hash, giving every participant a collision-resistant Delta table name. The identifier supports ownership and cleanup but is not a permission boundary.

The lab never modifies `hc_workshop.core_lending`. Its analytical FPD5 dataset is a session-scoped temporary view and therefore does not need a participant prefix.

## Definition of done

- The participant notebook reaches its final checkpoint without an unexpected error.
- The promotion FPD5 rate is higher than the non-promotion rate using the declared eligible population.
- The participant changes `ANALYSIS_DIMENSION`, reruns the breakdown, and explains how the selected grain changes the interpretation.
- The participant can explain why the pattern is an investigation signal, not proof of fraud.
- The participant-specific investigation table shows a pre-evolution and post-evolution version.
- The dashboard and Metric View use the same FPD5 definition as the notebook.
- Each participant creates one private Genie Agent in their own user folder using only `hc_workshop.workshop_shared.fpd_metrics`.
- The Agent is not shared with other participants, and its answer is checked against generated SQL and the governed Metric View result.
- The participant locates a section-generated SQL statement and can distinguish a queue symptom from a spill symptom.
- The participant can name the owner, compute dependency, permissions, monitoring location, and recovery action for each inherited analytical asset.
